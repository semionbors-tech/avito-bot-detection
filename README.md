# avito-bot-detection
# Avito Bot Detection (Data Science Bootcamp)

Решение задачи бинарной классификации куки-файлов на предмет принадлежности к ботам (автоматизированным сервисам сбора данных).

##Описание задачи
Даны исторические данные о событиях пользователей (просмотры, поиски, контакты). Необходимо построить модель, которая предсказывает вероятность того, что `cookie_id` принадлежит боту (`target = 1`). Метрика качества — **Precision при Recall ≥ 70%** на скрытой тестовой выборке.

##Подход к решению

### 1. Обработка данных и временные окна
*   События фильтруются строго в рамках окна наблюдения для каждого `cookie_id`: `window_start_ts <= event_ts < window_end_ts`. Это исключает утечку будущих данных.
*   Данные очищены от дубликатов и обработаны пропуски.

### 2. Генерация признаков (Feature Engineering)
Основной упор сделан на поведенческие паттерны, отличающие ботов от людей:
*   **Временные признаки (Timing):**
    *   Статистика интервалов между событиями (Inter-Event Time): среднее, медиана, стандартное отклонение, перцентили.
    *   Доля "сверхбыстрых" интервалов (< 0.1 сек, < 0.5 сек, < 1 сек). Боты часто кликают быстрее человека.
    *   Количество сессий (разрыв > 30 минут), средняя длительность сессии.
    *   Активность в ночное время (с 23:00 до 06:00).
*   **Разнообразие (Diversity):**
    *   Энтропия распределения категорий товаров, локаций, продавцов и поисковых запросов.
    *   Количество уникальных объявлений, категорий, платформ и User-Agent'ов на одну куку.
*   **Технические признаки:**
    *   Флаги User-Agent: наличие `okhttp`, `Avito App`, `HeadlessChrome`, `python-requests`, `curl`, `Scrapy`, `Go-http-client`.
    *   Соотношение пропусков в полях `item_id`, `search_query`, `pointer_x`, `pointer_y`.
    *   Статистика координат курсора (среднее, дисперсия, уникальность).
*   **Поисковая активность:**
    *   Средняя и максимальная страница выдачи.
    *   Доля поисковых запросов с page > 1.

### 3. Валидация
Используется **time-based split**: последние 20% дат из `train` выделены в валидацию. Это имитирует реальное тестирование на будущих данных. Случайный сплит здесь не подходит из-за временной природы данных.

### 4. Моделирование
*   **Baseline:** `RandomForestClassifier` на простейших признаках (кол-во событий, уникальные товары).
*   **Улучшенная модель:** `LightGBM` (или `HistGradientBoostingClassifier` как fallback) на полном наборе сгенерированных признаков с подбором гиперпараметров и балансировкой классов (`class_weight='balanced'`).

## Структура репозитория
*   `solve.py` — основной скрипт пайплайна (чтение данных, генерация признаков, обучение, предсказание).
*   `metric.py` — официальная реализация метрики Precision@Recall>=0.7.
*   `requirements.txt` — зависимости проекта.
*   `submission.csv` — итоговый файл с предсказаниями.
